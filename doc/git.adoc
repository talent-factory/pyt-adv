== Einführung in die Versionskontrolle mit Git
include::locale/attributes-de.adoc[]
:imagesdir: images/

In der modernen Softwareentwicklung ist die Versionskontrolle nicht mehr wegzudenken.
Sie bildet das Fundament für strukturierte, nachvollziehbare und kollaborative
Softwareentwicklung. Als angehende Softwareentwickler werden Sie täglich damit
konfrontiert sein.

=== Warum Versionskontrolle?

* *Änderungsverfolgung*: Dokumentation aller Änderungen am Quellcode
* *Zusammenarbeit*: Ermöglicht paralleles Arbeiten mehrerer Entwickler
* *Backup*: Sicherung aller Versionen des Codes
* *Experimentieren*: Gefahrloses Testen neuer Features in separaten Branches

=== Git - Das Standardwerkzeug

Git wurde 2005 von Linus Torvalds entwickelt und hat sich zum De-facto-Standard in
der Softwareentwicklung entwickelt. Im Gegensatz zu älteren Versionskontrollsystemen
ist Git:

* *Dezentral*: Jeder Entwickler hat eine vollständige Kopie des Repositories
* *Schnell*: Optimiert für Performance
* *Branching-fokussiert*: Ermöglicht effizientes paralleles Arbeiten

=== Installation von Git

Zunächst müssen Sie Git auf Ihrem System installieren:

[source,bash]
----
# Für Ubuntu/Debian
sudo apt-get install git

# Für macOS (mit Homebrew)
brew install git

# Für Windows
# Laden Sie Git von https://git-scm.com/download/win herunter
----

=== Konfiguration von Git

Nach der Installation ist die grundlegende Konfiguration erforderlich:

[source,bash]
----
# Setzen des Benutzernamens
git config --global user.name "Max Mustermann"

# Setzen der E-Mail-Adresse
git config --global user.email "max.mustermann@beispiel.de"

# Überprüfen der Konfiguration
git config --list
----

=== Initialisierung von Git

[source,bash]
----
# Erstellen eines neuen Verzeichnisses
mkdir mein-projekt
cd mein-projekt

# Initialisieren des Git-Repositories
git init

# Überprüfen des Status
git status
----

=== Grundlegende Befehle

Der typische Workflow in Git besteht aus drei Stufen:

1. Working Directory (Arbeitsverzeichnis)
2. Staging Area (Zwischenablage)
3. Repository (finale Versionen)

[source,bash]
----
# Datei zum Staging-Bereich hinzufügen
git add README.md

# Alle Änderungen hinzufügen
git add .

# Commit der Änderungen
git commit -m "Initiale Version des Projekts"

# Status überprüfen
git status
----

=== Remote Repositories

GitHub, GitLab oder andere Git-Hosting-Dienste ermöglichen das kollaborative Arbeiten:

[source,bash]
----
# Remote Repository hinzufügen
git remote add origin https://github.com/benutzername/repository.git

# Überprüfen der Remote-Verbindung
git remote -v

# Lokale Änderungen hochladen
git push -u origin master

# Änderungen vom Remote Repository holen
git pull origin master
----

=== Wichtige Remote-Operationen

[source,bash]
----
# Klonen eines existierenden Repositories
git clone https://github.com/benutzername/repository.git

# Alle Branches anzeigen
git branch -a

# Änderungen fetchen ohne zu mergen
git fetch origin

# Specific branch auschecken
git checkout -b feature-branch origin/feature-branch
----

=== Best Practices

Gute Commit-Nachrichten sind essentiell für die Nachvollziehbarkeit:

[source,bash]
----
# Beispiel für einen guten Commit
git commit -m "feat: Implementiere Login-Funktionalität

- Füge Benutzerauthentifizierung hinzu
- Implementiere Session-Handling
- Erstelle grundlegendes Login-Formular"
----

=== .gitignore

Die `.gitignore`-Datei definiert, welche Dateien nicht versioniert werden sollen:

[source,text]
----
# Beispiel .gitignore
node_modules/
*.log
.env
.DS_Store
----

=== Übungsaufgaben

1. Initialisieren Sie ein neues Git-Repository für Ihr Projekt
2. Erstellen Sie eine README.md und committen Sie diese
3. Erstellen Sie einen neuen Branch "feature-1"
4. Führen Sie Änderungen durch und mergen Sie diese in den master-Branch
5. Verbinden Sie Ihr lokales Repository mit GitHub

=== Probleme und Lösungen

==== Merge-Konflikte lösen

[source,bash]
----
# Bei einem Merge-Konflikt
git status
# Dateien manuell editieren
git add .
git commit -m "fix: Löse Merge-Konflikte"
----

==== Änderungen rückgängig machen

[source,bash]
----
# Letzen Commit rückgängig machen
git reset --soft HEAD~1

# Änderungen in einer Datei verwerfen
git checkout -- dateiname.txt
----
